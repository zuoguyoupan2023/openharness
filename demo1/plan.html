⚡ DeepSeek Harness · Tauri 封装蓝图

📦 将 DSH Web UI 包装为 Mac 原生应用 · 内置终端交互 · 无需浏览器
✅ 终端在 Tauri 后台进程中运行 —— 当 App 启动时，Rust 后端会 spawn 一个子进程执行 npx @deepseek-ai/dsh web。
📡 我们将 stdout / stderr 实时流式传输到前端界面，因此“终端”完全嵌入在应用壳内，用户看到的就是一个带日志输出的图形界面。

🚀 第一阶段 MVP

启动即运行 · 内置 WebView 加载 DSH 界面
1. 应用启动 (Tauri Main) Rust 后端执行 std::process::Command，调用 sh -c "npx @deepseek-ai/dsh web"。
✅ 无需 chmod，无需手动打开终端。
⬇
2. 监听端口就绪 通过捕获 stdout 输出，检测到 Running on http://127.0.0.1:3080 即表示服务已启动。
⬇
3. 自动导航 前端 WebView 使用 window.location.href 或 Tauri API 跳转到 http://127.0.0.1:3080。
🔒 完全不依赖外部浏览器，全在 App 窗口内交互。
💡 用户体验： 双击 .app → 看到启动日志 → 自动跳转到 DSH 聊天界面。

🖥️ 第二阶段 专业版

终端面板嵌入壳内 · 双向交互
1. 分屏 UI 架构 主区域左侧（70%）：加载 DSH Web 界面；右侧/底部（30%）：嵌入式终端面板。
⬇
2. 实时日志流 Rust 后端通过 Channel 将 stdout/stderr 逐行推送到前端，终端面板滚动显示。 🔧 包含 ANSI 颜色转义解析，还原终端原生体验。
⬇
3. 命令输入 (进阶) 在终端面板底部提供输入框，允许用户向 DSH 进程发送 stdin 指令（如重启、调试），实现真正的“壳中交互”。
🛠️ 技术栈： Rust (Tauri) + 前端 (React/Vue) + xterm.js 渲染终端仿真器。

📄 启动子进程 (Rust)

use tauri::api::process::Command; #[tauri::command] fn start_dsh() -> Result<String, String> { let mut cmd = Command::new("sh") .args(&["-c", "npx @deepseek-ai/dsh web"]) .spawn() .map_err(|e| e.to_string())?; // 通过 channel 向前端推送输出 Ok("进程已启动".into()) }

📟 前端接收日志 (JS)

import { listen } from '@tauri-apps/api/event'; listen('dsh-output', (event) => { const payload = event.payload; // 追加到终端面板 (如 xterm.js) terminal.write(payload); }); // 检测服务就绪后自动跳转 if (output.includes('Running on')) { window.location.href = 'http://127.0.0.1:3080'; }
🔑
关于「权限」与「首次运行」

Tauri 应用本身是 已签名 的 .app 包，双击即可运行。
首次启动时，npx 会自动检测并下载 @deepseek-ai/dsh 包（耗时取决于网络）。
整个过程在 App 的嵌入式终端面板内可视化显示，用户无需打开系统终端或执行任何 chmod 操作。

⚡ 按此方案开发，即可获得一个双击即用、内置终端、无需浏览器的 DeepSeek Harness 原生客户端。
